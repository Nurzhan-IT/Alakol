3. Categories of Personal Data

3.1. We process the following categories of personal data according to the HMS User model:

3.1.1. Account Data:

  • surname, first name, patronymic (full_name)
  • email address (email) - used as username, unique
  • phone number (phone)
  • gender (gender) - male/female
  • country and city of residence (country, city)
  • residential address (address)
  • password (encrypted using Django)
  • profile photo (image)
  • OTP code for verification
  • electronic wallet (wallet) - for future bonus programs
  • verification status (verified)

3.1.2. Booking Data (according to Booking model):

  • guest full name (full_name)
  • guest email (email)
  • country code (country_code)
  • phone number (phone)
  • selected hotel (hotel)
  • room type (room_type)
  • specific rooms (room) - many-to-many relationship
  • selection data (selection_data) - JSON field
  • check-in and check-out dates (check_in_date, check_out_date)
  • number of days (total_days)
  • number of adults and children (num_adults, num_children)
  • check-in/check-out status (checked_in, checked_out)
  • unique booking ID (booking_id)
  • Robokassa transaction ID (robokassa_inv_id)
  • preferences and special requests

3.1.3. Payment Information:

  • bank card data (processed by Robokassa payment system)
  • payment and transaction information
  • payment identifiers
  • amount before discount (before_discount)
  • total amount (total)
  • savings amount (saved)
  • payment status (payment_status)
  • applied coupons (coupons)

3.1.4. Technical Data:

  • IP address
  • browser and device information
  • cookies
  • visit logs and user actions
  • session times
  • system fields: booking activity (is_active), creation time (created_at), expiration time (expires_at)

3.1.5. Behavioral Data:

  • hotel search history
  • room selection preferences
  • service usage frequency
  • HMS interface interaction analytics

4.1. Personal data is processed for the following purposes:

4.1.1. Providing Booking Services:

  • processing booking requests through HMS booking module
  • booking confirmation and modification
  • communication with hotels for accommodation arrangements

4.1.2. Ensuring HMS System Operation:

  • user registration and authentication through userauths module
  • OTP system for verification
  • interface personalization
  • security assurance
  • management through user_dashboard module

4.1.3. Communications:

  • sending booking confirmations
  • notifying about order changes
  • technical support in Kazakh, Russian, and English
  • marketing messages (with consent)

4.1.4. Analytics and Service Improvement:

  • HMS system usage analysis through search and addon modules
  • functionality improvement
  • statistical research

4.1.5. Legal Compliance:

  • fulfilling Kazakhstan legislation requirements
  • fraud prevention
  • dispute resolution

5. Processing Methods

5.1. Personal data processing is carried out using Django 4.2.2 automation tools and without them.

5.2. Processing methods include:

  • collection, systematization, accumulation, storage in PostgreSQL database

6. Processing Terms

6.1. Personal data is processed for the following terms:

6.1.1. Account Data:

Until consent withdrawal or account deletion application is submitted.

6.1.2. Booking Data:

For 5 years after the last booking completion for accounting reporting and dispute resolution purposes.

6.1.3. Technical Data:

For 1 year from the last HMS system visit.

6.1.4. Payment Information:

In accordance with Kazakhstan financial legislation requirements and Robokassa policy.

6.1.5. Unpaid Bookings:

Automatically deleted 10 minutes after payment deadline expiration.
