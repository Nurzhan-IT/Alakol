# Настройка AWS SES для отправки email

## Обзор

Этот проект теперь поддерживает отправку email через AWS SES (Simple Email Service) в функции `robokassa_result`. Система отправляет два типа email при подтверждении оплаты:

1. **Email пользователю**: Благодарность за использование платформы eKol с деталями бронирования
2. **Email отелю**: Уведомление о новом оплаченном бронировании

## Настройка AWS SES

### 1. Создание AWS аккаунта и настройка SES

1. Зарегистрируйтесь в AWS Console: https://aws.amazon.com/
2. Перейдите в сервис **Amazon SES**
3. Выберите регион (ap-southeast-1 - Сингапур поддерживает AWS SES)
4. Подтвердите ваш домен или email адрес в разделе "Verified identities"

### 2. Получение AWS credentials

1. Перейдите в **IAM (Identity and Access Management)**
2. Создайте нового пользователя для SES
3. Прикрепите политику `AmazonSESFullAccess` к пользователю
4. Создайте Access Key и Secret Access Key
5. Сохраните их в безопасном месте

### 3. Настройка переменных окружения

Добавьте следующие переменные в ваш `.env` файл:

```bash
# AWS SES Configuration
AWS_ACCESS_KEY_ID=your_aws_access_key_id
AWS_SECRET_ACCESS_KEY=your_aws_secret_access_key
AWS_REGION=ap-southeast-1
```

**Важно**: Замените значения на ваши реальные AWS credentials.

### 4. Настройка DEFAULT_FROM_EMAIL

Убедитесь, что в `.env` файле указан корректный email отправителя:

```bash
DEFAULT_FROM_EMAIL=noreply@your-domain.com
```

Этот email должен быть подтвержден в AWS SES.

## Структура кода

### Основные файлы

1. **`hotel/aws_ses.py`** - Класс `AWSSESEmailSender` для работы с AWS SES
2. **`hotel/views.py`** - Обновленная функция `robokassa_result` с поддержкой AWS SES
3. **`hms_prj/settings.py`** - Конфигурация AWS SES

### Особенности реализации

- **Fallback механизм**: Если AWS SES не настроен, система автоматически переключается на старый способ отправки email
- **Обработка ошибок**: Все ошибки отправки email логируются, но не блокируют обработку платежа
- **Двуязычный контент**: Email содержат HTML и текстовые версии
- **Профессиональный дизайн**: HTML email имеют стилизованный дизайн

## Тестирование

### Песочница AWS SES

В режиме песочницы AWS SES можете отправлять email только на подтвержденные адреса. Для производственного использования подайте заявку на выход из песочницы.

### Мониторинг

1. Проверьте логи Django на наличие сообщений об отправке email
2. Используйте AWS CloudWatch для мониторинга метрик SES
3. Проверьте статистику отправки в консоли AWS SES

## Примеры email

### Для пользователя
- **Тема**: "Спасибо за бронирование с eKol! - ID: #abc123"
- **Содержание**: 
  - Благодарность за бронирование
  - Детали бронирования с датами на русском языке (например: "15 января 2025 г. (среда)")
  - **Важная информация о чеке**: инструкции по скачиванию и печати
  - Ссылка на чек бронирования для заселения
  - Многоязычные ссылки на чеки (русский, казахский, английский)

### Для отеля
- **Тема**: "Новое подтверждение бронирования - ID: #abc123"
- **Содержание**: 
  - Уведомление об оплаченном бронировании
  - Детали гостя и бронирования с датами на русском языке
  - Контактная информация гостя

## Безопасность

1. **Никогда не коммитьте** AWS credentials в репозиторий
2. Используйте **переменные окружения** для всех конфиденциальных данных
3. Регулярно **ротируйте** AWS Access Keys
4. Ограничьте **права доступа** IAM пользователя только необходимыми для SES

## Поддержка

Если возникли проблемы:

1. Проверьте логи Django
2. Убедитесь, что AWS credentials корректны
3. Проверьте, что email адреса подтверждены в AWS SES
4. Убедитесь, что AWS SES не находится в режиме песочницы для production

## Структура логов

Система логирует следующие события:

- Успешная отправка email пользователю
- Успешная отправка email отелю  
- Ошибки отправки с детальным описанием
- Использование fallback механизма

## Производительность

- Отправка email через AWS SES не блокирует обработку платежа
- Все ошибки обрабатываются gracefully
- Система автоматически переключается на резервный способ при недоступности AWS SES
