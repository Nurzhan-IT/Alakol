# Отключенные типы кэширования для данных реального времени

Данный документ описывает типы кэширования, которые были отключены в проекте для обеспечения обновлений в реальном времени.

## ✅ ОТКЛЮЧЕННЫЕ ТИПЫ КЭШИРОВАНИЯ

### 1. **Сессии пользователей** 
- **Местоположение:** `hms_prj/settings.py`
- **Изменение:** `SESSION_ENGINE = "django.contrib.sessions.backends.db"` (было: `cache`)
- **Причина:** Сессии изменяются при каждом действии пользователя и должны быть актуальными

### 2. **Бронирования пользователей**
- **Местоположение:** `hotel/templatetags/cache_tags.py` - функция `cached_user_bookings_count()`
- **Изменение:** Убрано использование `CacheHelper.get_or_set_complex()`
- **Причина:** Статус бронирований может изменяться мгновенно

### 3. **Динамические цены номеров**
- **Местоположение:** `hotel/templatetags/cache_tags.py` - функция `room_price_for_date()`
- **Изменение:** Убрано кэширование цен
- **Причина:** Цены могут изменяться в зависимости от спроса и времени

### 4. **Проверка доступности номеров**
- **Местоположение:** `booking/views.py` - функция `check_room_availability()`
- **Изменение:** Отключен декоратор `@cache_booking_function` и кэширование результатов
- **Причина:** Доступность изменяется при каждом новом бронировании

### 5. **Данные сессии бронирования**
- **Местоположение:** `booking/views.py` - функция `add_to_selection()`
- **Изменение:** Отключены вызовы `BookingCacheHelper.cache_booking_session_data()`
- **Причина:** Корзина должна отражать актуальное состояние выбора

### 6. **Пользовательские отзывы**
- **Местоположение:** `hotel/views.py` - функция `hotel_detail()`
- **Изменение:** Убрано кэширование отзывов пользователя
- **Причина:** Отзывы пользователя могут изменяться часто

### 7. **Уведомления пользователей**
- **Местоположение:** `hotel/context_processor.py` и `user_dashboard/views.py`
- **Статус:** ✅ Уже не кэшировались (загружаются напрямую из БД)
- **Причина:** Уведомления должны отображаться мгновенно

### 8. **✅ Пользовательские данные в топ-баре (КРИТИЧНО)**
- **Местоположение:** 
  - `hotel/context_processor.py` - функция `default()`
  - `templates/partials/base.html` - счетчик выбранных номеров
  - `templates/partials/base_seo.html` - счетчик выбранных номеров
  - `hotel/views.py` - новый API endpoint `get_selected_items_count()`
  - `static/scripts/custom.js` - обновление счетчика
- **Проблема:** `total_selected_items` кэшировался вместе со страницей и показывал одинаковое значение для всех пользователей
- **Решение:** 
  - Удалена переменная `total_selected_items` из context processor'а
  - Создан API endpoint `/api/selected-items-count/` для получения данных в реальном времени
  - Добавлен JavaScript для динамической загрузки значения при загрузке страницы
  - Обновлен `custom.js` для использования нового API при обновлении счетчика
- **Причина:** Данные о выбранных номерах персональны для каждого пользователя и должны обновляться мгновенно

### 9. **🚨 Django Messages (КРИТИЧЕСКАЯ ПРОБЛЕМА БЕЗОПАСНОСТИ)**
- **Местоположение:**
  - `templates/partials/base.html` - отображение messages
  - `templates/partials/dashboard_base.html` - отображение messages
  - `templates/partials/async_base.html` - отображение messages
  - `hotel/views.py` - новый API endpoint `get_messages()`
  - `hotel/urls.py` - URL для API messages: `/api/messages/`
  - `static/scripts/custom.js` - автоматическая загрузка messages после операций
- **КРИТИЧЕСКАЯ ПРОБЛЕМА:** Messages кэшировались вместе со страницей, что означало:
  - ❌ Сообщения об ошибках одного пользователя показывались другим
  - ❌ Персональная информация в сообщениях становилась доступной всем
  - ❌ Предупреждения о платежах могли вводить в заблуждение других пользователей
  - ❌ Устаревшие сообщения отображались долгое время
  - ❌ Новые важные сообщения не показывались до истечения кэша (15 минут!)
- **Решение:** 
  - Удалены все Django template loops `{% for message in messages %}`
  - Создан API endpoint `/api/messages/` для получения messages в реальном времени
  - Добавлен JavaScript `loadAndDisplayMessages()` для динамической загрузки
  - Messages автоматически очищаются после получения через API
  - Добавлено автоматическое обновление messages после пользовательских операций
- **Причина:** Messages содержат ПЕРСОНАЛЬНУЮ информацию и НИ В КОЕМ СЛУЧАЕ не должны кэшироваться!

## ⚠️ ДОПОЛНИТЕЛЬНЫЕ РЕКОМЕНДАЦИИ

### Данные, которые СЛЕДУЕТ рассмотреть для отключения кэширования:

1. **Профильные данные пользователя**
   - Аватар, настройки, предпочтения
   - Могут изменяться в активной сессии

2. **Текущие остатки номеров (инвентарь)**
   - Количество доступных номеров
   - Критично для предотвращения перебронирования

3. **Статусы платежей**
   - Статус оплаты бронирований
   - Должны обновляться немедленно после платежа

4. **Данные корзины/выбора номеров**
   - Выбранные номера, количество
   - Пользователь активно изменяет состав
