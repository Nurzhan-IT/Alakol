1. ОБЩИЕ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

1.1. Системные требования для работы с Платформой:
- Стабильное интернет-соединение (минимум 10 Мбит/с)
- Современный веб-браузер (Chrome 90+, Firefox 88+, Safari 14+, Edge 90+)
- Поддержка JavaScript и cookies
- Разрешение экрана не менее 1024x768 пикселей

1.2. Технические характеристики Платформы:
- Backend: Django 4.2.2 (Python web framework)
- База данных: PostgreSQL
- Платежная система: Robokassa.kz
- Мультиязычность: Казахский, русский, английский языки
- Временная зона: Asia/Yekaterinburg (UTC+5)
- Шифрование: SSL/TLS (HTTPS)

2. РЕГИСТРАЦИЯ И НАСТРОЙКА ПРОФИЛЯ ОТЕЛЯ

2.1. Процедура регистрации:
- Создание учетной записи на платформе через веб-интерфейс
- Верификация email-адреса (обязательно)
- Подтверждение мобильного телефона via SMS/OTP
- Предоставление документов для верификации отеля

2.2. Обязательные данные для профиля отеля (модель Hotel):
- Название отеля (name) - максимум 100 символов
- Описание отеля (description) - подробное текстовое описание
- Главное изображение отеля (image) - форматы: JPG, PNG, максимум 5MB
- Полный адрес (address) - максимум 200 символов
- Мобильный телефон (mobile) - максимум 20 символов, формат: +7XXXXXXXXXX
- Email отеля (email) - рабочий email для связи с гостями
- Время заезда (check_in_time) - формат: HH:MM (например, 14:00)
- Время выезда (check_out_time) - формат: HH:MM (например, 12:00)

2.3. Дополнительные параметры:
- Период работы отеля (start_date, end_date) - если отель сезонный
- Статус публикации (Draft/Live/Disabled) - управление видимостью
- Уникальный идентификатор (hid) - генерируется автоматически
- SEO-дружественная ссылка (slug) - генерируется автоматически

3. УПРАВЛЕНИЕ НОМЕРНЫМ ФОНДОМ

3.1. Типы номеров (модель RoomType):
- Название типа номера (type) - максимум 120 символов
- Базовая цена за ночь (price) - в тенге, формат: XXXXX.XX
- Динамическое ценообразование (dynamic_pricing) - JSON-формат для особых дат
- Количество кроватей (number_of_beds) - целое число
- Вместимость номера (room_capacity) - максимальное количество гостей
- Размер номера (room_size) - площадь в квадратных метрах

3.2. Конкретные номера (модель Room):
- Номер комнаты (room_number) - уникальный в рамках отеля
- Доступность для бронирования (is_available) - boolean
- Привязка к типу номера (room_type) - обязательная связь

3.3. Дополнительная информация о номерах:
- Описание типа номера (RoomTypeDescription)
- Галерея изображений номера (RoomTypeGallery) - до 10 фото
- Список удобств (RoomTypeFeatures) - иконки и названия
- Детальные характеристики (RoomTypeFeaturesDetailed)

4. СИСТЕМА ЦЕНООБРАЗОВАНИЯ

4.1. Базовое ценообразование:
- Указание цены за ночь для каждого типа номера
- Цены указываются в казахстанских тенге (KZT)
- Возможность установки разных цен для будних и выходных дней

4.2. Динамическое ценообразование (JSON-формат):
```json
{
  "2025-07-01": 25000,
  "2025-07-02": 30000,
  "2025-12-31": 50000,
  "weekend_multiplier": 1.2,
  "holiday_multiplier": 1.5
}
```

4.3. Рекомендации по ценообразованию:
- Учитывать сезонность и местные праздники
- Устанавливать конкурентоспособные цены
- Регулярно анализировать и корректировать цены
- Использовать скидки и специальные предложения

5. ИНТЕГРАЦИЯ С ПЛАТЕЖНОЙ СИСТЕМОЙ ROBOKASSA

5.1. Схема работы платежей:
- Клиент оплачивает 10% от общей стоимости через Robokassa
- Платформа получает предоплату и подтверждает бронирование
- Отель получает информацию о подтвержденном бронировании
- При заселении клиент доплачивает оставшиеся 90% в отеле

5.2. Настройки интеграции:
- Поддержка тестового и реального режимов Robokassa
- Автоматическая генерация безопасных подписей SHA256
- Время жизни платежа: 10 минут с момента создания
- Поддерживаемые валюты: KZT (тенге)

5.3. Обработка платежных уведомлений:
- ResultURL: автоматическое подтверждение оплаты
- SuccessURL: перенаправление после успешной оплаты
- FailURL: обработка неуспешных платежей
- Все уведомления обрабатываются в реальном времени

6. УПРАВЛЕНИЕ БРОНИРОВАНИЯМИ

6.1. Информация о бронированиях (модель Booking):
- Данные гостя: ФИО, email, телефон, код страны
- Информация о проживании: даты заезда/выезда, количество дней
- Количество гостей: взрослые и дети отдельно
- Выбранные номера и тип номера
- Финансовая информация: общая сумма, предоплата, доплата

6.2. Статусы бронирований:
- initiated: Создано, ожидается оплата
- paid: Оплачено, подтверждено
- pending: В обработке
- cancelled: Отменено
- failed: Ошибка оплаты
- refunded: Возвращено

6.3. Автоматические процессы:
- Отправка уведомлений отелю при новом бронировании
- Автоматическая отмена неоплаченных бронирований через 10 минут
- Email-уведомления клиентам о статусе бронирования
- Синхронизация данных с системой отеля
