# ОТЧЕТ О ПРОЕКТЕ HMS ДЛЯ ПОДГОТОВКИ ЮРИДИЧЕСКИХ ДОКУМЕНТОВ

Дата составления: 30.05.2025
Версия отчета: 1.0

## ОБЩАЯ ИНФОРМАЦИЯ О ПРОЕКТЕ

### Основные характеристики:
- **Название проекта**: HMS (Hotel Management System) - Система управления отелями Alakol
- **Тип системы**: Веб-платформа для бронирования отелей 
- **Технологическая платформа**: Django 3.2.18 (Python web framework)
- **База данных**: PostgreSQL
- **Платежная система**: Robokassa (официальная интеграция)
- **Мультиязычность**: Поддержка казахского, русского и английского языков
- **Временная зона**: Kazakhstan/Astana (UTC+5)

### Архитектура проекта:
Проект состоит из следующих основных модулей:
1. **hotel** - управление отелями, номерами, бронированиями
2. **booking** - функциональность бронирования
3. **userauths** - аутентификация и управление пользователями
4. **user_dashboard** - личный кабинет пользователя
5. **robokassa** - интеграция платежной системы
6. **search** - поиск отелей
7. **addon** - дополнительные функции

### Основные функции проекта:
- Регистрация и аутентификация пользователей
- Поиск и фильтрация отелей по различным критериям
- Просмотр детальной информации об отелях и номерах
- Система бронирования номеров с проверкой доступности
- Интегрированная система оплаты через Robokassa
- Управление бронированиями через личный кабинет
- Система уведомлений по email и SMS
- Мультиязычный интерфейс

## ДЕТАЛЬНЫЙ АНАЛИЗ ФУНКЦИОНАЛЬНОСТИ

### 1. ПРОЦЕСС РЕГИСТРАЦИИ И АУТЕНТИФИКАЦИИ

#### Модель пользователя (User):
**Собираемые обязательные данные:**
- Email (используется как username, уникальный)
- Пароль
- Имя пользователя (username)

**Дополнительные данные профиля:**
- Полное имя (full_name)
- Номер телефона (phone)
- Пол (gender) - мужской/женский
- Страна проживания (country)
- Город проживания (city)
- Адрес (address)
- Фотография профиля (image)
- OTP код для верификации
- Электронный кошелек (wallet) - для будущих бонусных программ
- Статус верификации (verified)

#### Особенности регистрации:
- Автоматическое создание профиля при регистрации пользователя
- Email конвертируется в нижний регистр
- Система OTP для верификации
- Отсутствуют чекбоксы согласия на обработку персональных данных (ТРЕБУЕТ ДОРАБОТКИ)

### 2. ПРОЦЕСС БРОНИРОВАНИЯ

#### Этапы бронирования:
1. **Поиск отелей**: По городу, датам заезда/выезда, количеству гостей
2. **Выбор номера**: Просмотр доступных типов номеров и цен
3. **Проверка доступности**: Автоматическая проверка свободных номеров
4. **Заполнение данных**: Контактная информация гостя
5. **Оплата**: Предоплата 10% через Robokassa
6. **Подтверждение**: Отправка данных в отель и клиенту

#### Модель бронирования (Booking):
**Основные данные:**
- Связь с пользователем (user)
- Полное имя гостя (full_name) 
- Email гостя (email)
- Код страны (country_code)
- Номер телефона (phone)
- Выбранный отель (hotel)
- Тип номера (room_type) 
- Конкретные номера (room) - связь многие-ко-многим
- Данные о выборе (selection_data) - JSON поле
- Даты заезда и выезда (check_in_date, check_out_date)
- Количество дней (total_days)
- Количество взрослых и детей (num_adults, num_children)
- Статусы заселения/выселения (checked_in, checked_out)
- Уникальный ID бронирования (booking_id)
- ID транзакции Robokassa (robokassa_inv_id)

**Финансовые данные:**
- Сумма до скидки (before_discount)
- Итоговая сумма (total)
- Сумма экономии (saved)
- Статус оплаты (payment_status)
- Примененные купоны (coupons)

**Системные поля:**
- Активность бронирования (is_active)
- Время создания (created_at)
- Время истечения (expires_at) - 10 минут для завершения оплаты
- Трекеры заселения/выселения (для внутреннего использования)

#### Схема оплаты:
- **Предоплата**: 10% от общей стоимости через Robokassa
- **Доплата**: 90% оплачивается при заселении в отель
- **Назначение предоплаты**: Гарантия серьезности намерений и подтверждение бронирования

### 3. ПЛАТЕЖНАЯ СИСТЕМА ROBOKASSA

#### Интеграция и настройки:
- Полная интеграция с Robokassa.kz
- Поддержка тестового и реального режимов
- Генерация безопасных цифровых подписей SHA256
- Автоматическая обработка уведомлений от платежной системы


#### Безопасность платежей:
- Использование HTTPS для всех транзакций
- Шифрование данных при передаче (SSL/TLS)
- Соответствие стандартам PCI DSS
- Платежные данные не сохраняются на серверах проекта
- Обработка только через сертифицированную платежную систему

#### Особенности расчета:
- Комиссия платежной системы включена в стоимость
- Динамическое ценообразование в зависимости от даты
- Поддержка купонов и скидок
- Автоматическое истечение неоплаченных бронирований через 10 минут

### 4. УПРАВЛЕНИЕ ОТЕЛЯМИ

#### Модель отеля (Hotel):
**Основная информация:**
- Название отеля

#### Модель типа номера (RoomType):

## РИСКИ И РЕКОМЕНДАЦИИ

### Критические правовые риски:

#### 1. **Обработка персональных данных без согласия**
- **Риск**: Нарушение закона РК о персональных данных
- **Последствия**: Штрафы до 100 МРП, приостановка деятельности
- **Решение**: Внедрить систему согласий на обработку ПД

#### 2. **Отсутствие пользовательского соглашения**  
- **Риск**: Невозможность регулирования спорных вопросов
- **Последствия**: Проблемы в судебных разбирательствах
- **Решение**: Создать и внедрить пользовательское соглашение

#### 3. **Отсутствие публичной оферты**
- **Риск**: Нарушение требований ГК РК к публичным договорам
- **Последствия**: Недействительность договорных отношений
- **Решение**: Разработать публичную оферту на услуги

#### 4. **Неясные условия отмены и возврата**
- **Риск**: Споры с клиентами о возврате средств
- **Последствия**: Жалобы в ОЗП, репутационные риски
- **Решение**: Четко прописать правила отмены и возврата

## ОСОБЕННОСТИ ИНТЕГРАЦИИ С ROBOKASSA

### Правовые аспекты платежной системы:
- Robokassa является лицензированной платежной системой
- Соответствует требованиям финансового законодательства РК
- Обеспечивает защиту платежных данных по стандартам PCI DSS
- Предоставляет юридически значимые документы об оплате

### Схема ответственности:
- **Платформа отвечает за**: Корректность передачи данных о платеже
- **Robokassa отвечает за**: Обработку платежа и безопасность данных
- **Пользователь отвечает за**: Достоверность платежной информации

### Документооборот:
- Автоматическая генерация электронных чеков
- Уведомления о статусе платежей
- Возможность получения справок об оплате
- Соответствие требованиям налогового учета

## ЗАКЛЮЧЕНИЕ

✅ Качественная техническая реализация
✅ Безопасная интеграция с платежной системой  
✅ Мультиязычность и локализация
✅ Продуманная система бронирования

Критические недостатки:
